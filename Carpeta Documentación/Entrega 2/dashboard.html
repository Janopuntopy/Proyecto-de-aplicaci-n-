Microservicios en Google Cloud Run

Nuestra arquitectura backend está compuesta por 8 microservicios individuales desarrollados en Java 17 con Spring Boot y Spring Security. Cada microservicio está contenerizado en una imagen optimizada con Docker y desplegado de forma serverless en Google Cloud Run con certificados SSL públicos HTTPS, conectándose dinámicamente a Firestore.

EventoMicroservice

Activo

Gestión completa del ciclo de vida de los torneos: creación de borradores, publicación, inicio y finalización del evento.

https://evento-microservice-902749656527.us-central1.run.app/api/eventos

Flujo & Arquitectura del Sistema

El sistema implementa una arquitectura híbrida serverless de alta respuesta y sincronización nativa. Visualiza a continuación el recorrido detallado de los paquetes de datos a través de nuestros microservicios independientes e infraestructura en la nube:

Capa 1

Cliente Móvil Híbrido

Frontend compilado a código nativo utilizando Ionic Framework, Angular y Capacitor. Maneja la renderización fluida de UI a 120Hz, criptografía local de sesiones, y el escaneo nativo de códigos QR con MLKit.

HTTPS TLS 1.3 / JWT Auth
Capa 2

GCP Load Balancer & Ingress

Punto de entrada único, global y seguro. Realiza el balanceo de carga, resolución de políticas CORS estrictas y enrutamiento inteligente (Path-based Routing) hacia el clúster de microservicios serverless correctos.

Serverless VPC Routing
Capa 3

Clúster de Microservicios (Cloud Run)

Arquitectura distribuida en 8 microservicios independientes, escritos en Java 17 (Spring Boot). Escalan automáticamente a cero o a cientos de instancias según el tráfico competitivo.

Seguridad & Calidad Institucional

Nuestra arquitectura de confianza "Zero Trust" garantiza la integridad del sistema mediante validaciones estrictas y métricas exhaustivas.

GCP API Gateway & Load Balancer

Escudo perimetral global. El balanceador de carga de Google Cloud enmascara las IPs reales de los microservicios Cloud Run, gestiona y fuerza certificados SSL/TLS, resolviendo además ataques DDoS volumétricos antes de que toquen el clúster.

Autenticación Delegada (Firebase Auth)

Manejo robusto de identidades respaldado por Google. Implementamos validación estricta de Tokens JWT de corta duración, evitando inyecciones y garantizando que cada petición a los microservicios viaje debidamente firmada criptográficamente.

Spring Security

Filtros de acceso (CORS/CSRF) estrictos por microservicio, aislando los entornos.

Guards de Rutas

Protección en Ionic/Angular: bloqueo de vistas sensibles sin el rol correcto (Admin).

QA & Testing

Pruebas unitarias/integración (JUnit) que evitan regresiones antes de desplegar CI/CD.

Reglas de Seguridad NoSQL

Validación atómica a nivel de documento en Firestore. Prevenimos que usuarios no autenticados alteren el leaderboard o las rondas manipulando directamente la base de datos distribuida de Google.

Telemetría GCP

Vigilancia en vivo en Cloud Console: consumos de CPU, cuellos de botella y errores HTTP 500.

Calidad ISO/Android

Cumplimiento de Play Store Policies y aseguramiento de mantenibilidad (ISO/IEC 25010).

Soporte Inteligente de Antigravity (Google DeepMind)

El diseño arquitectónico de Guild Letter y la robustez de sus integraciones serverless contaron con el soporte de Antigravity, el potente agente autónomo de inteligencia artificial creado por el equipo de Advanced Agentic Coding en Google DeepMind. Actuando como un programador de par en par, Antigravity aceleró el desarrollo mediante:

Spring Security CORS: Resolución analítica de filtros de acceso y orquestación de seguridad HTTP 403 para dominios Capacitor.
Optimización Docker: Configuración e instrumentación de JVM Eclipse Temurin JDK 17 en contenedores reducidos y ligeros.
Arquitectura Cloud Run: Soporte de despliegue en contenedores serverless dinámicos bajo demanda en GCP.
Firestore Integration: Estructuración ágil y segura del SDK Firestore Admin para sincronía de scores y timers en vivo.
Nuevo Asistente IA (n8n + Gemini): Integración de un Chatbot inteligente en la app móvil que utiliza flujos visuales de n8n para orquestar llamadas a la API de Gemini, entregando respuestas precisas y conversacionales sobre las reglas de Magic: The Gathering.
